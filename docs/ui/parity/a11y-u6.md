# Parity note — U6 accessibility hardening

**Change type:** presentation / semantics only — label associations, focus
management, and ARIA wiring. No data, API, route, permission, auth, form
value, validation rule, or handler change. Every fix is additive markup/focus
behaviour; no control's action changes.

## Audit first — what was already correct (left untouched)

- **Live regions** — `States.tsx` already ships `role="alert"` on `ErrorState`
  and `role="status"`/`aria-busy` on `Loading` + `TableSkeleton`, so errors and
  loading are announced. The U4 offline banner is `role="status" aria-live`.
- **Skip link** — the shell renders `<a class="mn-skip" href="#main">` and
  `<main id="main" tabIndex={-1}>`.
- **Modals** — `Dialog`/`Drawer`/`ConfirmDialog` already had `role="dialog"`,
  `aria-modal`, Escape-to-close, backdrop-close, and (Dialog/Drawer) focus-in +
  focus-restore.
- **Checkbox/file labels** — the 5 raw `<label>`s in the app (orders, tracking,
  company, roles, admin/plans) all **wrap** their control → valid implicit
  association. No change needed.

## What U6 changed

| # | Gap | Fix | Leverage |
|---|---|---|---|
| 1 | **143 `<Field>` usages, none tied the label to its control** (`htmlFor` was optional and never passed). | `Field` now generates an id with `useId()`, points `htmlFor` at the single child control, and wires `aria-describedby` to the help/error text. Callers can still pass an explicit `htmlFor` to opt out; a child with its own `id` is respected. | **1 component → ~103 labelable fields** (Input/select/input/Select). The ~10 `<div>`/`<Button>` children don't associate but don't regress. |
| 2 | Modals had focus-**in** + restore but **no focus trap** — Tab could leave the dialog and land on the page behind it (WCAG 2.4.3 / keyboard-trap counterpart). | New shared `useFocusTrap(ref, active)` hook cycles Tab/Shift+Tab within the panel. Wired into `Dialog`, `Drawer`, and `ConfirmDialog`. | 1 hook → every modal in the app. |
| 3 | `ConfirmDialog` had no focus trap, no focus restore, and its **prompt `<label>` was unassociated**. | Added panel `ref` + `tabIndex={-1}`, focus trap, focus-restore (captured at call time so the prompt's `autoFocus` doesn't clobber the trigger reference), and `htmlFor`/`id` on the prompt label+input. | — |

New files: `lib/use-focus-trap.ts`. Touched: `Field.tsx`, `Dialog.tsx`,
`Drawer.tsx`, `ConfirmDialog.tsx`, plus a `Field` demo added to `/ui-kit`.

markup (probe was throwaway — not committed):

## Behaviour preserved (regression checklist)

- [x] `useId` is SSR-stable → no hydration mismatch; SSR/first paint unchanged.
- [x] `Field` clones the child only to add `id`/`aria-describedby` (never when the
      caller supplied `htmlFor` or the child already has an `id`) → input values,
      `onChange`, `aria-invalid` (set by MasterCrud) all intact.
- [x] Focus trap only intercepts the **Tab** key inside an open modal; Escape,
      backdrop-close, submit, and every button action are unchanged.
- [x] Prompt `autoFocus` still lands on the input; focus returns to the exact
      trigger on close (captured before autoFocus moves it).
- [x] `/ui-kit` baselines refreshed for the added Field demo; all other sections
      pixel-identical.
- [x] typecheck / build (ESLint) green — re-verified.
